## 一、整体架构

### 1.1 IndexedDB 存储设计

```
数据库: ledu_english_db (version 1)

Object Stores:
├── knowledge_points    — 知识点库（词汇/语法/短语等）
├── review_records      — 复习记录（SM-2 算法状态）
├── error_records       — 错题记录
├── daily_plans         — 每日学习计划
├── settings            — 全局设置
└── stats               — 每日统计数据
```

### 1.2 实体关系

```
knowledge_points (1) ──── (1) review_records      每个知识点有一条复习记录
knowledge_points (1) ──── (N) error_records       一个知识点可能多次出错
daily_plans    (1) ──── (N) knowledge_points      每日计划包含多个知识点
stats          (1) ──── (1) daily_plans            每日统计对应一个计划
```

## 二、知识点 Schema（knowledge_points store）

### 2.1 通用结构

```typescript
interface KnowledgePoint {
  // === 唯一标识 ===
  id: string;              // 稳定唯一ID，生成规则见第四节
  contentHash: string;     // 内容哈希（SHA-256前16位），用于增量更新比对

  // === 分类 ===
  type: KPType;            // 知识点类型
  // KPType = "vocabulary" | "grammar" | "phrase" | "phonics" | "irregular_verb" | "reading_vocab"

  // === 来源信息 ===
  source: {
    grade: string;         // "1" | "2" | "3" | "4"
    term: string;          // "预备一级秋" | "预备二级春" | "2B秋季" | "3B夏季" 等
    unit: string;          // "L1" | "U1" | "秋L5" 等
    section: string;       // "vocabulary" | "grammar" | "reading" | "phonics"
    file: string;          // 源文件相对路径
  };

  // === 内容（按type不同，使用不同字段） ===
  content: VocabularyContent | GrammarContent | PhraseContent | PhonicsContent | IrregularVerbContent;

  // === 状态 ===
  status: "active" | "archived";  // archived = 增量更新时源文件已删除，暂停复习
  confidence: "high" | "medium" | "low";  // 数据置信度（OCR来源标记为low）

  // === 时间戳 ===
  createdAt: number;       // 创建时间（毫秒）
  updatedAt: number;       // 最后更新时间
}
```

## 三、复习记录 Schema（review_records store）

### 3.1 结构

```typescript
interface ReviewRecord {
  kpId: string;            // 关联的知识点ID（主键）
  kpType: KPType;          // 冗余字段，避免查询时join

  // === SM-2 算法状态 ===
  status: "new" | "learning" | "review" | "mastered";
  // new:       从未学过
  // learning:  正在学习（首次学习后1天内）
  // review:    进入间隔复习
  // mastered:  连续答对≥5次且间隔≥21天

  interval: number;        // 当前间隔（天）
  ease: number;            // 难度系数（初始2.5，最小1.3）
  reps: number;            // 连续答对次数（答错归零）
  lapses: number;          // 遗忘次数（答错导致重置的总次数）

  // === 时间 ===
  createdAt: number;       // 首次学习时间
  lastReview: number;      // 上次复习时间（毫秒时间戳）
  nextReview: number;      // 下次到期时间（毫秒时间戳）

  // === 统计 ===
  totalReviews: number;    // 总复习次数
  totalCorrect: number;    // 总答对次数
  avgResponseMs: number;   // 平均响应时间（毫秒）
}
```

### 3.2 状态流转

```
new ──(首次学习)──→ learning ──(1天后复习)──→ review ──(连续答对5次+间隔≥21天)──→ mastered
  ↑                    |                        |                                       |
  └────────────────────┘                        │                                       │
        (重置)                                   │                                       │
                                         (答错→lapse)                                 │
                                              ↓                                       │
                                         interval=1                                   │
                                         reps=0                                      │
                                         ease-=0.2                                   │
                                         status=review                               │
                                             │                                       │
                                             └───────────────────────────────────────┘
                                              (重新进入复习循环)
```

## 八、唯一ID生成规则

### 8.1 设计目标

- **稳定性**：文件行号/顺序变化不影响ID
- **可追溯**：从ID可定位到来源年级/学期/单元/板块
- **变化检测**：内容修改可通过contentHash检测

### 8.2 ID格式

```
{grade}_{term}_{unit}_{section}_{contentHash}

示例: 4_3B夏季_U1_vocabulary_a1b2c3d4e5f6a7b8
```

| 字段 | 说明 | 示例 |
|------|------|------|
| grade | 年级数字 | `1` `2` `3` `4` |
| term | 学期标识（原文） | `3B夏季` `预备二级秋` `2B春季` |
| unit | 单元/课次 | `U1` `L5` `秋L5` |
| section | 板块 | `vocabulary` `grammar` `reading` `phonics` |
| contentHash | 内容哈希 | SHA-256(归一化内容) 前16位hex |

### 8.3 contentHash 计算

```python
import hashlib
import json

def compute_content_hash(content: dict, kp_type: str) -> str:
    """计算知识点的contentHash"""
    # 按类型提取核心标识字段
    if kp_type == "vocabulary":
        key_fields = {"word": content["word"].lower().strip()}
    elif kp_type == "grammar":
        key_fields = {"title": content["title"].strip()}
    elif kp_type == "phrase":
        key_fields = {"phrase": content["phrase"].lower().strip()}
    elif kp_type == "irregular_verb":
        key_fields = {"base": content["base"].lower().strip()}
    elif kp_type == "phonics":
        key_fields = {"letter": content["letter"], "sound": content["sound"]}
    elif kp_type == "reading_vocab":
        key_fields = {"phrase": content["phrase"].lower().strip()}
    else:
        key_fields = content

    # 归一化：排序key + JSON序列化 + 编码
    normalized = json.dumps(key_fields, sort_keys=True, ensure_ascii=False)
    return hashlib.sha256(normalized.encode('utf-8')).hexdigest()[:16]
```

### 8.4 完整ID生成

```python
def generate_kp_id(grade, term, unit, section, content, kp_type) -> str:
    """生成知识点唯一ID"""
    content_hash = compute_content_hash(content, kp_type)
    # 清理特殊字符
    term_clean = term.replace(" ", "").replace("/", "-")
    unit_clean = unit.replace(" ", "")
    return f"{grade}_{term_clean}_{unit_clean}_{section}_{content_hash}"
```

### 8.5 增量更新比对逻辑

```python
def diff_knowledge_points(old_db: dict, new_scan: dict) -> dict:
    """
    增量比对：对比已有知识库与新扫描结果
    返回: {added: [], updated: [], archived: []}
    """
    old_ids = set(old_db.keys())
    new_ids = set(new_scan.keys())

    added = []      # 新增：新扫描中有，旧库中没有
    updated = []    # 更新：ID相同但contentHash不同
    archived = []   # 归档：旧库中有，新扫描中没有

    for kp_id in new_ids - old_ids:
        added.append(new_scan[kp_id])

    for kp_id in old_ids & new_ids:
        if old_db[kp_id]["contentHash"] != new_scan[kp_id]["contentHash"]:
            updated.append({
                "kpId": kp_id,
                "old": old_db[kp_id],
                "new": new_scan[kp_id],
                # 注意：保留原有review_record不清零
            })

    for kp_id in old_ids - new_ids:
        archived.append(old_db[kp_id])

    return {"added": added, "updated": updated, "archived": archived}
```

### 9.2 导入逻辑

```javascript
async function importData(jsonData) {
  const db = await openDB();

  // 1. 知识点：按ID比对，新增/更新/保留
  for (const kp of jsonData.knowledgePoints) {
    const existing = await db.get('knowledge_points', kp.id);
    if (!existing) {
      await db.put('knowledge_points', kp);
    } else if (existing.contentHash !== kp.contentHash) {
      // 内容更新：更新知识点，保留复习记录
      await db.put('knowledge_points', { ...kp, updatedAt: Date.now() });
    }
  }

  // 2. 复习记录：仅导入不存在的新记录，不覆盖已有进度
  for (const rr of jsonData.reviewRecords) {
    const existing = await db.get('review_records', rr.kpId);
    if (!existing) {
      await db.put('review_records', rr);
    }
  }

  // 3. 错题记录：全部导入（按ID去重）
  for (const er of jsonData.errorRecords) {
    await db.put('error_records', er);
  }

  // 4. 设置：合并（用户当前设置优先）
  const currentSettings = await db.get('settings', 'app');
  await db.put('settings', { ...jsonData.settings, ...currentSettings });
}
```

## 十一、数据量估算与容量

| 数据类型 | 估计条数 | 单条大小 | 总大小 |
|---------|---------|---------|--------|
| knowledge_points | ~1,053 | ~500B | ~520KB |
| review_records | ~1,053 | ~200B | ~210KB |
| error_records | ~500(估) | ~300B | ~150KB |
| daily_plans | ~365/年 | ~2KB | ~730KB |
| stats | ~365/年 | ~200B | ~73KB |
| settings | 1 | ~500B | ~500B |

IndexedDB 在 iOS Safari 上的配额通常为 **可用磁盘空间的 50%**（GB级别），1.7MB/年的数据量远在安全范围内。但仍提供导出/导入功能防止 Safari 清除缓存。

## 十二、设计决策说明

| 决策 | 理由 |
|------|------|
| 知识点与复习记录分离存储 | 增量更新时知识点内容变化不影响复习进度 |
| contentHash 用归一化内容计算 | 大小写/空格变化不触发误更新 |
| 错题记录独立store而非嵌入复习记录 | 同一知识点可能多次出错，需保留完整错误历史 |
| daily_plans 按日期为主键 | 快速查询某天计划，支持补打卡 |
| 设置存储在IndexedDB而非localStorage | 统一存储层，且localStorage有5MB限制 |
| 不规则动词单独type | 其复习逻辑与普通词汇不同（需同时考原形和过去式） |
